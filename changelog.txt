= 6.9.0 =
* Fixed: the free version from wordpress.org included some Pro price formatting code, left in by a misnamed function, and a Pro-only function that would have stopped the site if anything had called it. Neither is in the free version any more
* Fixed: licences on the first paid plan (2017) and the older High Powered plan sold in 2018 and 2019 now get the High Powered features (the premium layouts, the popup and the other High Powered options in shortcodes, blocks and Elementor). Since that plan was retired they only had the basic Pro options
* Fixed: free trials of Professional or High Powered taken without a payment method now get those plans' layouts and options; since 6.5.0 they only had the Starter ones. The block editor and Elementor now offer the same options for each plan as the shortcode
* Fixed: when Eventbrite can't be reached or returns an error, including a revoked API key, visitors now always see the last events fetched instead of an error every couple of minutes, which a page cache could then keep showing
* Fixed: the saved copy of events used when Eventbrite fails was renewed for another month on every failure, so a site could silently show old events, or none once they had all passed, for weeks. It is now used for at most a week (or two cache periods if longer, changeable with the wfea_eventbrite_backup_max_age filter)
* Added: an admin notice when Eventbrite events can't be refreshed, naming the API key, the error and the date of the events visitors are being shown. It clears by itself once a call succeeds
* Added: EventKiln event descriptions keep their formatting (bold, italics, lists and links) in the full description and the details pop-up, once EventKiln sends formatted descriptions. Plain-text descriptions show as before (Pro Only)
* Fixed: the Account page showed the Account tab twice
* Added: EventKiln events show their own organiser, with logo, description and website, in the details pop-up and wherever the organiser name is shown, once EventKiln sends organiser profiles. Until then, or when an event has none, the EventKiln organisation is shown as before (Pro Only)
* Changed: the EventKiln settings box now offers Create your free account instead of Request access, as anyone can now sign up to EventKiln
* Changed: the EventKiln settings box no longer leads with using EventKiln without Eventbrite, and its fee line now says Stripe's card fees are charged separately
* Fixed: pages with the Display Eventbrite Layouts or Calendar block loaded the block editor's scripts (about 1 MB, render-blocking) on the front end, which slowed page loads and hurt PageSpeed scores. The blocks' Pro editor controls now load only in the editor (Pro Only)
* Fixed: for EventKiln events whose tickets are sold on the organiser's own site, the Book Now screen reader label said "on EventKiln". It now names only the event
* Fixed: with the popup option on, lists showing only EventKiln events, and sites with no Eventbrite key, no longer load Eventbrite's checkout script from eventbrite.com, so visitors' browsers don't contact Eventbrite for nothing (Pro Only)
* Fixed: sites with no Eventbrite key, such as those using only EventKiln, no longer call the Eventbrite API with an empty key and log "Authorization header format invalid". The "Eventbite" typo in debug log messages is also fixed

= 6.8.0 =
* Security: the plugin no longer bundles symfony/process 3.4, kriswallsmith/assetic or robloach/component-installer. They came in only to install the calendar files, were never used, and symfony/process has known Windows advisories (CVE-2024-51736, CVE-2026-24739) that security scanners would flag. The calendar files are unchanged
* Added: show events from EventKiln alongside your Eventbrite events, or on their own with no Eventbrite key. Add your EventKiln API key under Settings, EventKiln. EventKiln events appear in date order in every layout and the calendar, with prices, tickets left, sold out, not yet on sale and postponed (Pro; postponed once EventKiln supports it), music details and line-up (Pro), and Get Tickets going to the EventKiln ticket selector or to the organiser's own ticket site
* Added: EventKiln events are fetched in the background on the same schedule as Eventbrite results are cached (once a day, or the Pro Manage Cache setting, or the wfea_eventbrite_cache_expiry filter, never more often than every 5 minutes) and when the settings are saved. The last good copy is kept, so if EventKiln is unreachable or the key is revoked visitors still see the events and the admin gets a notice saying why
* Added: with the popup option on, Get Tickets for an EventKiln event opens EventKiln's checkout in a pop-up on your site, in every layout and the calendar. The organiser adds the website under EventKiln Settings, Checkout on your own website. If the checkout script is blocked the button still goes to the event page, and it needs no cookie consent as it sets no cookies (Pro Only)
* Added: the EventKiln settings box explains what EventKiln is, with links to request access, find out more and see pricing, until EventKiln is connected; once connected it links to managing your events in EventKiln
* Added: with the details pop-up on (long_description_modal), Read More on an EventKiln event opens the same full details pop-up as Eventbrite events, with Add to Calendar and the EventKiln checkout pop-up (Pro Only)
* Added: in the details pop-up, EventKiln events use EventKiln's own calendar links for Google, Outlook, Apple and Yahoo, the venue links to a map, and the venue's accessibility and travel notes are shown (Pro Only)
* Added: instant updates for EventKiln events. If the EventKiln API key has the webhooks permission, the site subscribes to EventKiln webhooks when the settings are saved, and EventKiln tells it within about 2 minutes when tickets sell or an event changes, so sold out and edits show without waiting for the next refresh. Notices are checked against their signature and the refetch runs in the background. Turn it off with Instant updates in the EventKiln settings; it needs https, and is re-enabled automatically if EventKiln switched it off while the site was down (Pro Only)
* Added: EventKiln events follow the status filter like Eventbrite events. Cancelled EventKiln events are hidden by default and shown with status="canceled" or "all", with the Canceled button (Pro); past events show with status="ended" or "all", with the past event button (Pro). Past events are fetched only while a list asks for them, so the first view after adding such a list shows them once the background refresh has run
* Fixed: an EventKiln event that finished since the last refresh counted as started until the next refresh; it now counts as ended
* Added: staging sites (WP_ENVIRONMENT_TYPE staging) can point at another EventKiln, as development sites already could
* Added: venue_id filters EventKiln events too, with EventKiln venue IDs written as ek-12 (Pro Only)
* Fixed: the Outlook Calendar and Apple Calendar buttons in the details pop-up did nothing, as the pop-up removed their forms (Pro Only)
* Fixed: the details pop-up ignored the list's settings, such as the excerpt length, and always used the defaults, so it had no Get Tickets button (Pro Only)
* Fixed: with the popup option on, Get Tickets did nothing on themes that load pages without a full page load (such as Waveme) when visitors reached the events page from the site's menu, or when the Eventbrite script was blocked. The checkout pop-up is now set up when the events arrive, however the page was loaded, and until it is ready, or if it is blocked, the button links to the event on Eventbrite (Pro Only)
* Fixed: the details pop-up button (Read More / View details) was missing whenever Full content was on. The block turns Full content on by default, so in the One, Grid, Venue, Slide Show and Accordion layouts the block had no button while the equivalent shortcode did (Pro Only)
* Fixed: activating Pro while the free plugin was active (or the reverse) showed "The plugin generated unexpected output during activation", because the second copy redefined the plugin's constants and PHP warned. The second copy now hands over to the first before defining anything
* Fixed: PHP warnings (Attempt to read property "id" on null, Undefined property venue / organizer) when the Elementor widget built its venue or organizer list and some events had no venue, such as online events
* Fixed: in the block editor, Pro plan controls such as Show Availability appeared twice, and layouts and plans were added twice, because the Pro block filters were registered twice (since 6.5.0) (Pro Only)
* Fixed: Show Availability set in the Display Eventbrite Events block was not saved, because the block attribute was misnamed. Existing blocks keep availability off (0), as the shortcode does (Pro Only)
* Fixed: Read More on EventKiln events went to the ticket selector instead of the event page
* Fixed: screen reader labels and link titles on EventKiln events said "on Eventbrite"; they now say EventKiln. The free Book Now button's screen reader label read "%4$s" instead of the event title
* Fixed: Add to Calendar links for Google, Yahoo and Outlook.com put the event at the wrong time outside UTC (an hour late for UK events in summer), and events with no end time got a wrong end. The downloaded calendar file was already right (Pro Only)
* Fixed: "Sold Out" shown as the availability of Eventbrite events whose tickets are sold on another website, where the number of tickets left is not known (Pro Only)
* Added: choose which events a list shows with source="all" (the default), "eventbrite" or "eventkiln" on the shortcode, and Show Events From on the blocks and Elementor widget once an EventKiln API key is set. An EventKiln-only list doesn't call Eventbrite at all
* Added: for developers, wfea_include_eventkiln_events, wfea_eventkiln_event, wfea_eventkiln_event_url and wfea_eventkiln_widget_src filters, and a wfea_eventkiln_order_complete jQuery event on document with { orderReference, eventId } (Pro); EventKiln events carry original_system "eventkiln" and an eventkiln property with the EventKiln id and URLs
